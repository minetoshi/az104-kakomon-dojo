課金リスク項目 詳細操作マニュアル

実際に有料リソースを作らず、Azure Portalでどこを開き、何を選び、何を確認するかを「ハードコピー風」に追う教材です。試験では、画面名よりも 目的・前提条件・設定の方向 を答えられる状態を目標にします。

このページでは Create / Save / Enable の最終確定を押す必要はありません。 項目名・選択肢・依存関係を読めれば十分です。Azure Portal UIは更新されるため、場所が少し変わっても「何の設定を探しているか」で追えるようにしてください。

↑上へ1. Private Endpoint

目的: Storage、SQL、Key Vault、App ServiceなどのPaaSへ、VNet内のprivate IPで到達する構成を理解します。

Client VM→VNet / Subnet→Private Endpoint NIC→Private Link→PaaS
対象PaaS ＞ Networking ＞ Private endpoint connections ＞ + Private endpoint
Resource groupPrivate Endpointを置くRG
Namepe-storage01 等
Target resourceStorage / SQL / App Service 等
Target sub-resourceblob / file / sites 等
Virtual network接続元VNet
SubnetPrivate Endpoint用のSubnet
Private DNS integration通常はYesを検討
1Resource / sub-resourceを選ぶ
StorageでもBlobとFileではPrivate DNS zone名が変わります。
2VNet / Subnetを選ぶ
Private Endpoint用NICに、そのSubnetからprivate IPが割り当てられます。
3DNS連携を見る
FQDNをprivate IPへ解決するにはPrivate DNS zoneとの関連が重要です。
4Public accessを別設定として考える
Private Endpointを作っただけでPublic network accessが必ず無効になるわけではありません。要件に応じてPaaS側のpublic accessを制御します。
試験の決め手: 「PaaSにVNet内のprivate IPを持たせたい」→ Private Endpoint。
「PaaSのpublic endpointは維持し、特定Subnetを信頼したい」→ Service Endpoint。
理解チェック

Q: App ServiceからVNet内SQLへ出ていく通信はPrivate Endpoint？
A: App Service側はVNet Integration。Private Endpointは主にPaaSへのinbound private access。

試験ミニ問題 3問

Q1. PaaSにVNet内のprivate IPを持たせる機能は？
答え: Private Endpointです。
Q2. Private Endpoint作成後もPublic accessが残ることはある？
答え: あります。PaaS側のPublic network accessは別途確認します。
Q3. FQDNをprivate IPへ解決させる上で重要なものは？
答え: Private DNS zoneとVNet linkなどのDNS構成です。

↑上へ3. Azure Bastion

目的: VMへPublic IPを付けず、Portal/ブラウザ経由でRDP/SSHする構成を理解します。

試験: 「VMにPublic IPを付けず、安全にRDP/SSH」「ブラウザから接続」→ Bastion。

Q3. Bastionで無料実機が可能なSKUは？
答え: 対応リージョンで利用できるDeveloper SKUです。Basic/Standard/Premiumは有料です。

↑上へ8. Azure Site Recovery

目的: Test failover / Failover / Commit / Re-protect の順序を手順として覚えます。

Replication→Test failover→Failover→Validate→Commit→Re-protect

8-1. Enable replication の画面イメージ

Recovery Services vault ＞ Site Recovery ＞ Enable replication
SourcePrimary region / VM
TargetSecondary region / Resource group / VNet
Replication policyRecovery point retention等

8-2. Test failover

Vault ＞ Replicated items ＞ VM ＞ Test failover
Recovery pointLatest / Latest processed / App-consistent等
Test network本番影響を避ける隔離VNetを推奨
Test failover: 継続レプリケーションや本番環境に影響させずDR訓練を行う。

8-3. 本番 Failover → Commit

1Failover を開始しRecovery pointを選択。
2Secondary側VMが起動したらアプリ/接続を検証。
3問題なければ Commit。Commit後は別recovery pointへ戻せなくなる。
4将来Primaryへ戻すため Re-protect。
5逆方向レプリケーションが安定後、必要なタイミングでFailback。
試験で強い順序: Test failoverは訓練。実Failover後はValidate → Commit。逆方向レプリケーションはRe-protect。

よくある失敗・ひっかけ

  • Test failoverのテストVM/ネットワークをCleanupしない
  • Failover後すぐCommitして検証を飛ばす
  • Commit後にRecovery pointを変えられると思う
  • Failback前にRe-protectを忘れる

試験ミニ問題 3問

Q1. 本番影響を避けてDR訓練する操作は？
答え: Test failoverです。
Q2. Failover後、復旧VMを検証して問題なければ何をする？
答え: Commitです。
Q3. 元リージョンへ戻す準備として逆方向Replicationを開始する操作は？
答え: Re-protectです。
